## 2025-04-21 - Optimizing React Query Polling Intervals
**Learning:** Found several dashboard components across the `CredVerseRecruiter`, `CredVerseIssuer 3`, and `BlockWalletDigi` applications that are indiscriminately polling backend APIs using `refetchInterval` with extremely short intervals (5000ms - 10000ms). While intended for real-time updates, this causes severe frontend performance issues (unnecessary React re-renders) and heavily loads the backend infrastructure with redundant network requests, especially since there are no active websockets or Server-Sent Events (SSE) configured, and dashboard data rarely changes every 5 seconds.
**Action:** Extend the aggressive `refetchInterval` polling (e.g., from 5000ms to 30000ms - 60000ms) on non-realtime dashboard components. Active verification feeds where users expect real-time feedback can keep their short intervals, but aggregate dashboards should poll less frequently.
## 2025-04-21 - Parallelizing Sequential DB/Storage Calls
**Learning:** In routes that generate aggregate dashboard reports (e.g., `CredVerseIssuer 3/server/routes/activityLogs.ts` and `exports.ts`), I noticed multiple independent asynchronous data-fetching operations (e.g., `listCredentials`, `listStudents`, `listTemplateDesigns`, `listVerificationLogs`) were being `await`-ed sequentially. This causes a water-falling effect where the total latency is the sum of all individual query latencies, significantly slowing down report generation on large datasets.
**Action:** Always wrap independent, non-dependent asynchronous operations in `Promise.all()` to execute them concurrently. This reduces the total network/database latency to the duration of the slowest individual operation, instead of the sum of all operations.

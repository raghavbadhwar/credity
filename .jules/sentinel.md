## 2025-02-14 - Fix IDOR in Student Management API
**Vulnerability:** Missing authorization check on GET, PUT, and DELETE operations for students by ID in `CredVerseIssuer 3`. The `tenantId` of the authenticated user was not being compared to the `tenantId` of the requested student record, allowing any authenticated user to access, modify, or delete any student record by guessing the ID.
**Learning:** Centralized middleware (like `apiKeyMiddleware`) sets `req.tenantId` for authentication but database storage methods (e.g., `getStudent`) do not implicitly filter by `tenantId`. Relying solely on authentication middleware without explicit authorization checks per resource leads to Insecure Direct Object References (IDOR).
**Prevention:** Always verify that the fetched resource's `tenantId` matches the authenticated `req.tenantId` before returning or mutating data. Implement explicit authorization checks in route handlers for all operations that access specific resources by ID.

## 2024-05-24 - IDOR Vulnerability via Unvalidated userId parameter
**Vulnerability:** Insecure Direct Object Reference (IDOR) due to endpoints accepting `userId` from query parameters (`req.query.userId`) or body (`req.body.userId`) instead of deriving it securely from the authenticated token (`req.user?.userId`). Endpoints parse the value with `parseInt(req.query.userId) || 1` and do not verify if it matches the current user.
**Learning:** This widespread pattern essentially bypasses all authentication/authorization checks for accessing or mutating data because it accepts an untrusted input parameter as the basis for the user's identity, allowing any user to act as any other user (most commonly user ID 1).
**Prevention:** Always apply the `authMiddleware` to secure routes and strictly extract the `userId` from the verified JWT payload (`req.user.userId`). Do not allow the client to specify the user ID directly in requests without server-side validation against their token.

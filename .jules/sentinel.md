## 2025-05-05 - Insecure Direct Object Reference (IDOR) via Query Parameters
**Vulnerability:** Systemic IDOR and Authentication Bypass in BlockWalletDigi routes. The endpoints incorrectly parsed `userId` from untrusted request queries/bodies (e.g., `parseInt(req.query.userId as string) || 1`), allowing any user to access or modify data for arbitrary users. Additionally, defaulting to user ID `1` when the input was invalid led to a severe unauthenticated fallback vulnerability.
**Learning:** This vulnerability existed because the API relied on explicit client-provided context rather than strictly extracting identity from the verified session or JWT token payload. The lack of standard middleware enforcement exposed several critical routes.
**Prevention:** Always enforce route protection by applying the `authMiddleware` from `@credverse/shared-auth` to sensitive endpoints. Extract the `userId` strictly from the verified token payload (`req.user?.userId`) instead of trusting client inputs.

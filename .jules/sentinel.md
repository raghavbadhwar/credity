## 2025-02-23 - Prevent IDOR in Student Endpoints
**Vulnerability:** Insecure Direct Object Reference (IDOR) on student endpoints (`GET /students/:id`, `PUT /students/:id`, `DELETE /students/:id`). Centralized authentication (`apiKeyMiddleware`) sets `req.tenantId`, but the storage methods (`getStudent`, `updateStudent`, `deleteStudent`) do not implicitly filter by `tenantId`. A user could modify or delete another tenant's students.
**Learning:** Even with robust centralized tenant mapping in middleware, route handlers must explicitly verify that the fetched resource's `tenantId` matches the authenticated `req.tenantId` before returning or mutating data. Relying on middleware alone is insufficient if the data layer lacks tenant scoping.
**Prevention:** Always verify ownership (`resource.tenantId === req.tenantId`) in route handlers when accessing specific records by ID. When updating records, prevent Mass Assignment by explicitly stripping protected fields (like `tenantId`) from the request payload before passing it to storage.
